# Database Schema & Data Pipeline Documentation

This document outlines the database design, tables, data flows, and offline machine learning pipelines for the **What Do I Watch** application.

---

## 1. Database Roles & Locations

The application operates with two independent database layers:

1.  **Server-Side Database (`whatdoiwatch-app/data/app.db`)**:
    *   **Engine**: SQLite, queried via Drizzle ORM / `node:sqlite`.
    *   **Role**: Read-only reference corpus containing ~16k TMDB titles and precomputed similarity tables.
    *   **Access**: Server-side only (Expo API routes).
2.  **Client-Side Watchlist Database (Device local storage)**:
    *   **Engine**: SQLite via `expo-sqlite` on native platforms (iOS/Android), fallback to `localStorage` on Web.
    *   **Role**: Stores the user's interactive state (watchlist status, preferences, historical swipes).
    *   **Access**: Client-side only.

---

## 2. Schema Definitions

### Server Schema (`src/lib/db/schema.ts`)

#### `titles`
Primary storage of the TMDB corpus. Matches [MediaItem](file:///Users/samirhusain/Personal/code_projects/Whatdoiwatch/whatdoiwatch-app/src/lib/media.ts) interfaces.
*   `media_type` (text, primary key): `"movie"` or `"tv"`.
*   `id` (integer, primary key): TMDB identifier.
*   `title` (text): Screen display name.
*   `year` (integer, nullable): Release or air year.
*   `genres` (text / json): Array of TMDB genre IDs (`number[]`).
*   `vote_average` (real, nullable): Rating out of 10.
*   `poster_path` (text, nullable): Poster image path.
*   `overview` (text, nullable): Short plot synopsis.

#### `similar_titles`
Stores the similarity adjacency list generated by the offline pipeline.
*   `id` (integer, primary key auto-increment).
*   `src_type` (text): Origin type (`"movie"` | `"tv"`).
*   `src_id` (integer): Origin TMDB ID.
*   `dst_type` (text): Neighbor type (`"movie"` | `"tv"`).
*   `dst_id` (integer): Neighbor TMDB ID.
*   `score` (real): Cosine similarity value (0.0 to 1.0).
*   *Index: Index on `(src_type, src_id)` for high-performance recommendation queries.*

#### `api_cache`
Dynamic server-side response cache for external API calls.
*   `key` (text, primary key): Cached route query key.
*   `payload` (text / json): Response body.
*   `expires_at` (integer): Unix millisecond expiration time (typically 7 days for ratings).

---

### Client Schema (`src/lib/db/client-schema.ts`)

#### `watchlist`
Persists watchlist choices, swipes, and seen marks.
*   `media_type` (text, primary key): `"movie"` or `"tv"`.
*   `title_id` (integer, primary key): TMDB identifier.
*   `status` (text): `"want_to_watch"` | `"seen"` | `"not_interested"`.
*   `added_at` (integer): Date added (Unix millisecond).
*   `title` (text): Denormalized title text for offline access.
*   `poster_path` (text, nullable): Denormalized poster path for offline rendering.

#### `prefs`
Simple persistent key-value store for preferences.
*   `key` (text, primary key).
*   `value` (text / json): Arbitrary settings.

## 3. Dataset Pipeline (Build → Export → Seed)

To update the local recommendation corpus, run the pipeline scripts in `whatdoiwatch-app/scripts/`.

```
                  ┌──────────────────────┐
                  │      TMDB API        │
                  └──────────┬───────────┘
                             │ build_dataset.py
                             ▼
                  ┌──────────────────────┐
                  │ corpus.parquet (raw) │
                  └──────────┬───────────┘
                             │ export_neighbors.py
                             ▼
                  ┌──────────────────────┐
                  │  neighbors.json      │
                  │  titles_meta.json    │
                  └──────────┬───────────┘
                             │ seed.ts
                             ▼
                  ┌──────────────────────┐
                  │    SQLite app.db     │
                  └──────────────────────┘
```

### Step 1: Set up the Python Environment
```bash
cd whatdoiwatch-app
python3 -m venv scripts/.venv
scripts/.venv/bin/pip install -r scripts/requirements.txt
```

### Step 2: Build the Raw Corpus (`build_dataset.py`)
Queries TMDB `/discover` endpoint to download the top ~16k titles. It aggregates genres, keywords, cast, and directors for each entry.
*   **Test Run** (快速测试 ~500 entries):
    ```bash
    scripts/.venv/bin/python3 scripts/build_dataset.py --mode test
    ```
*   **Full Run** (Takes several hours, throttled for API compliance. Checkpointed to resume if interrupted):
    ```bash
    scripts/.venv/bin/python3 scripts/build_dataset.py --mode full
    ```
*   Outputs: `whatdoiwatch-app/data/corpus.parquet`

### Step 3: Compute Nearest-Neighbors (`export_neighbors.py`)
Applies scikit-learn's `CountVectorizer` and `cosine_similarity` to build a text "soup" from genres, keywords, directors, and actors.
*   Computes the top **20** nearest neighbors for each title across movies and TV series combined (enabling cross-recommendations).
*   Command:
    ```bash
    scripts/.venv/bin/python3 scripts/export_neighbors.py
    ```
*   Outputs: `whatdoiwatch-app/data/neighbors.json` and `whatdoiwatch-app/data/titles_meta.json`

### Step 4: Seed SQLite Database (`seed.ts`)
Parses the output JSON files and updates the tables inside the server SQLite database `app.db`.
*   Command:
    ```bash
    npx tsx scripts/seed.ts
    ```
